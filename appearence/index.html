appearance

Contrôle la restitution visuelle native des composants d'interface du système d'exploitation et permet de réinitialiser leur apparence pour les styliser librement.

📖 1. Explication

Par défaut, les navigateurs délèguent le rendu des éléments de formulaire (boutons, listes déroulantes <select>, cases à cocher <input type="checkbox">, sliders <range>) au système d'exploitation sous-jacent (Windows, macOS, iOS, Android). Ce mécanisme historique crée d'importantes disparités visuelles selon la plateforme de l'utilisateur.

La propriété appearance: none ordonne au navigateur de supprimer complètement le thème natif de l'OS appliqué à l'élément. Elle transforme le contrôle en une boîte neutre que l'on peut alors façonner intégralement avec du CSS ordinaire (bordures, fonds, dégradés, icônes SVG, animations).

Longtemps fragmentée sous les préfixes vendeurs -webkit-appearance et -moz-appearance, la propriété standard appearance: none est aujourd'hui universellement reconnue et incontournable pour concevoir des Design Systems sur-mesure.

💻 2. Syntaxe

La valeur reine est none, souvent accompagnée du préfixe -webkit- pour une compatibilité absolue :

CSS appearance-styling.css 
/* 1. Réinitialisation complète du look natif */
select,
input[type="checkbox"],
input[type="range"],
button {
  appearance: none;
  -webkit-appearance: none;
}

/* 2. Exemple : création d'un interrupteur (toggle switch) sur une checkbox pure */
.toggle-switch {
  appearance: none;
  width: 44px;
  height: 24px;
  background: #cbd5e1;
  border-radius: 9999px;
  position: relative;
  transition: background-color 0.2s ease;
}

.toggle-switch:checked {
  background-color: #4f46e5;
}

/* 3. Conservation du style natif standard */
.default-control {
  appearance: auto; /* comportement natif par défaut de l'OS */
}

💡 Statut Baseline Widely Available

La propriété appearance: none est présente dans tous les navigateurs modernes depuis des années. Pour couvrir d'anciens périphériques mobiles iOS/Android, conserver -webkit-appearance: none; dans vos règles est une bonne pratique recommandée.

🛡️ 5. Note sur le Fallback & Accessibilité

Quand et comment sécuriser vos interfaces lors de l'utilisation de appearance: none ?

  • Préserver impérativement les indicateurs de focus (:focus-visible) :
    En désactivant le thème système, l'anneau de focus par défaut disparaît souvent. Vous devez impérativement définir un style :focus-visible (avec outline ou box-shadow) pour garantir l'accessibilité aux utilisateurs navigant au clavier.
  • Rétablir les indicateurs visuels obligatoires :
    Sur un <select>, appearance: none retire la flèche native. Il faut donc toujours réinjecter une flèche personnalisée (par exemple via une image vectorielle SVG en arrière-plan avec background-image).
  • Compatibilité rétroactive avec préfixe vendeur :
    Assurez une transition douce sur les anciens moteurs WebKit en doublant la propriété : 
    .my-control {
  -webkit-appearance: none; /* Anciens iOS Safari & Chrome */
  appearance: none;         /* Standard moderne */
}
