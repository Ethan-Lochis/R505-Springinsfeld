@layer

Maîtrisez l'ordre de priorité de la cascade CSS sans surenchère de spécificité ni recours abusif à !important.

📖 1. Explication

L'un des défis historiques majeurs du CSS est la gestion des conflits de styles : lorsqu'une bibliothèque tierce (ex: Bootstrap, Tailwind) utilise des sélecteurs très spécifiques (comme .nav > ul > li.active a), écraser ces règles obligeait les développeurs à créer des sélecteurs encore plus longs ou à polluer le code avec des !important.

La règle @layer (Cascade Layers) introduit une hiérarchie explicite de couches. L'ordre des couches prime désormais sur la spécificité des sélecteurs : une règle déclarée dans une couche supérieure l'emportera toujours sur une règle d'une couche inférieure, même si le sélecteur de la couche supérieure est beaucoup plus court ou simple.

Les couches non ordonnées ou le code CSS classique situé hors de tout @layer conservent toujours la priorité maximale par défaut, assurant une intégration progressive et sans friction.

💻 2. Syntaxe

La déclaration de l'ordre des couches en haut de feuille de style permet d'établir la hiérarchie en un coup d'œil :

CSS cascade-layers.css 
/* 1. Définition explicite de l'ordre de priorité (de la moins prioritaire à la plus forte) */
@layer reset, framework, components, overrides;

/* 2. Couche basse : même avec une très haute spécificité, elle perd face aux couches supérieures */
@layer reset {
  body .site-header nav ul li.item a {
    color: #94a3b8;
  }
}

/* 3. Couche haute : un sélecteur de classe simple l'emporte facilement sans forcer */
@layer overrides {
  .btn {
    color: #10b981; /* Gagne sur toute règle des couches reset ou framework */
  background-color: #0f172a;
  }
}

/* 4. Importation directe d'une feuille externe dans une couche */
@import url("bootstrap.css") layer(framework);

🛡️ 5. Note sur le Fallback & Stratégies de Repli

Conseils d'architecture pour une transition sans casse :

  • Règle d'or de priorité non encapsulée :
    Tout CSS écrit en dehors d'une règle @layer possède une priorité supérieure à n'importe quelle couche ordonnée. Si un navigateur ignore @layer, il appliquera simplement l'ordre classique basé sur la spécificité des sélecteurs.
  • Organisation des imports :
    Enfermez les feuilles de style de bibliothèques tierces dans une couche de base dès l'import : 
    @import "vendor-library.css" layer(vendor);
    Cela garantit que votre propre code de composant prendra toujours le dessus sans conflit de sélecteurs.
