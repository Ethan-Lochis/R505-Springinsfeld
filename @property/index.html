@property

Enregistre et type des variables CSS personnalisées afin de permettre leur interpolation fluide, validation et valeur par défaut.

📖 1. Explication

Issue des spécifications CSS Houdini, la règle @property permet aux développeurs de définir explicitement le type de données d'une variable CSS personnalisée (Custom Property).

Par défaut, les variables CSS classiques sont traitées comme de simples chaînes de caractères sans type. Le navigateur est donc incapable de savoir comment les animer ou calculer des transitions entre deux états (par exemple pour faire tourner l'angle d'un dégradé ou modifier en douceur une couleur dans un gradient).

En déclarant un type précis (comme <color>, <angle>, <length> ou <percentage>), une valeur initiale et un comportement d'héritage, @property offre enfin la possibilité d'animer des dégradés et des valeurs mathématiques fluides directement en CSS pur, sans JavaScript.

💻 2. Syntaxe

La règle comporte trois descripteurs essentiels (syntax, inherits, initial-value) :

CSS property-syntax.css 
/* 1. Déclaration formelle de la variable typée */
@property --gradient-angle {
  syntax: '<angle>';         /* type : angle (deg, rad, turn) */
  initial-value: 0deg;       /* valeur par défaut obligatoire */
  inherits: false;           /* true ou false */
}

/* 2. Utilisation dans une transition ou une animation CSS */
.card {
  background: linear-gradient(var(--gradient-angle), #4f46e5, #ec4899);
  transition: --gradient-angle 0.5s ease;
}

.card:hover {
  --gradient-angle: 180deg; /* Le navigateur interpole l'angle de 0deg à 180deg ! */
}

🛡️ 5. Note sur le Fallback & Stratégies de Repli

Que se passe-t-il sur les navigateurs qui ne reconnaissent pas la règle @property ?

  • Comportement silencieux par défaut :
    Si un navigateur ne comprend pas @property, la variable reste une variable CSS standard non typée. Le composant s'affichera correctement avec sa valeur initiale, mais la transition ne sera pas fluide (changement brusque à l'état final sans interpolation intermédiaire).
  • Détection via CSS.registerProperty en JavaScript :
    Pour vérifier la prise en charge programmatique avant d'appliquer une animation gourmande : 
    if ('registerProperty' in CSS) {
  // Prise en charge native confirmée
} else {
  // Solution de repli alternative (ex: transition de clip-path ou opacity)
}
  • Fournir une apparence alternative simple :
    Pour les boutons ou cartes à dégradé, prévoyez un arrière-plan uni ou une transition classique sur opacity ou filter en cas d'absence de typage.
