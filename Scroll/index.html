Scroll-driven Animations

Liez directement l'avancement d'une animation CSS à la progression du défilement ou à la visibilité d'un élément dans le viewport, sans une seule ligne de JavaScript.

📖 1. Explication

Jusqu'alors, synchroniser une animation avec le scroll (par exemple une barre de progression de lecture, des effets parallaxe ou des apparitions d'éléments au défilement) imposait d'écouter l'événement JavaScript window.addEventListener('scroll', ...), puis de recalculer les positions avec des risques majeurs de saccades (jank) et de blocage du thread principal.

Les Scroll-driven Animations introduisent la propriété animation-timeline et les fonctions scroll() et view(). Au lieu d'avancer selon le temps écoulé en secondes, l'animation avance au prorata direct du défilement d'un conteneur ou du passage d'un élément devant l'écran.

Cette synchronisation s'effectue entièrement sur le thread du compositeur matériel du navigateur, offrant une fluidité absolue à 60/120 images par seconde tout en simplifiant drastiquement le code.

💻 2. Syntaxe

Deux modes principaux sont à votre disposition : scroll() (selon le scroll du conteneur) et view() (selon la visibilité du sujet) :

CSS scroll-driven-animations.css 
/* --- Mode 1 : Barre de progression basée sur le scroll du document --- */
.reading-progress {
  animation: grow-progress auto linear;
  animation-timeline: scroll(root block); /* ou scroll() pour le scroll parent */
}

@keyframes grow-progress {
  from { transform: scaleX(0); }
  to   { transform: scaleX(1); }
}

/* --- Mode 2 : Apparition fluide d'une carte au passage à l'écran --- */
.card {
  animation: reveal-item auto linear both;
  animation-timeline: view();
  animation-range: entry 15% cover 35%; /* plage d'intersection active */
}

@keyframes reveal-item {
  from { opacity: 0; transform: translateY(40px) scale(0.95); }
  to   { opacity: 1; transform: translateY(0) scale(1); }
}

🛡️ 5. Note sur le Fallback & Stratégies de Repli

Comment intégrer sereinement les Scroll-driven Animations en production aujourd'hui ?

  • Rendu par défaut fonctionnel sans animation :
    Assurez-vous que vos éléments sont visibles et lisibles sans animation (par exemple opacity: 1 par défaut). L'animation ne doit servir qu'à ajouter du dynamisme visuel.
  • Conditionnement via la règle @supports :
    Encapsulez les propriétés spécifiques au scroll dans une règle d'analyse pour isoler les navigateurs compatibles : 
    /* Styles de base : visibles par tous */
.fade-card {
  opacity: 1;
  transform: none;
}

/* Amélioration Scroll-driven si supporté */
@supports (animation-timeline: view()) {
  .fade-card {
    animation: reveal-item auto linear both;
    animation-timeline: view();
  }
}
  • Polyfill officiel du W3C / Chrome Labs :
    Un polyfill JavaScript officiel (scroll-timeline-polyfill) est disponible pour émuler le comportement exact sur Firefox et Safari en attendant leur publication définitive dans les versions stables.
