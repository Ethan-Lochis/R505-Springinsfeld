:has()

La pseudo-classe fonctionnelle relationnelle CSS qui permet de cibler un élément parent en fonction de ce qu'il contient.

📖 1. Explication

Historiquement attendue depuis les débuts de CSS, la pseudo-classe fonctionnelle :has() est souvent surnommée « le sélecteur parent ». Elle permet de styliser un élément en vérifiant s'il contient un ou plusieurs éléments spécifiques correspondant à une liste d'arguments, ou s'il est suivi par un élément frère précis.

Avant son apparition, cibler un parent selon l'état d'un de ses enfants (comme une case à cocher active, un champ invalide ou la présence d'une image) nécessitait impérativement d'écrire du JavaScript ou de concevoir des structures HTML complexes et rigides. Grâce à :has(), le code CSS devient purement déclaratif, réactif au DOM et considérablement plus concis.

Elle accepte une liste de sélecteurs relatifs et s'applique avec d'autres combinateurs (descendant direct >, adjacent direct +, général ~), ouvrant des possibilités autrefois impensables sans script.

💻 2. Syntaxe

Voici la structure de base et des cas d'usage typiques :

CSS syntaxe.css 
/* Syntaxe générale : cible l'élément s'il contient l'argument */
target:has(selector) {
  property: value;
}

/* Exemple 1 : styliser une carte de produit si sa checkbox est cochée */
.card:has(input[type="checkbox"]:checked) {
  border-color: #6366f1;
  background: #1e1b4b;
}

/* Exemple 2 : cibler un conteneur qui contient un badge de promotion */
.article:has(.badge-discount) {
  outline: 2px solid #ef4444;
}

/* Exemple 3 : styliser un formulaire lorsqu'un champ obligatoire est en erreur */
.form-group:has(input:focus:invalid) {
  border-color: #f87171;
}

🛡️ 5. Note sur le Fallback & Stratégies de Repli

Que se passe-t-il si un utilisateur navigue sur une ancienne version (ex: Firefox < 121 ou vieux navigateurs mobiles) ?

  • Invalidation de la règle (règle par défaut) :
    En CSS, si un navigateur rencontre un sélecteur qu'il ne comprend pas, l'intégralité du bloc de déclaration est ignorée. Veillez donc à ne pas grouper :has() avec d'autres sélecteurs standards sans précaution : 
    /* ⚠️ Mauvaise pratique : si :has n'est pas supporté, .active est ignoré aussi ! */
.card.is-active, .card:has(input:checked) { ... }

/* ✅ Bonne pratique : déclarer séparément ou utiliser :is() si besoin */
.card.is-active { ... }
.card:has(input:checked) { ... }
  • Détection native via @supports selector() :
    Vous pouvez conditionner vos styles avancés grâce à la directive @supports selector(...) : 
    /* Style de base / repli pour tout le monde */
.card {
  border: 1px solid #ccc;
}

/* Amélioration progressive pour les navigateurs compatibles */
@supports selector(:has(*)) {
  .card:has(input:checked) {
    border-color: #6366f1;
    box-shadow: 0 0 15px rgba(99, 102, 241, 0.4);
  }
}
  • Repli JavaScript (Graceful Degradation / Polyfill) :
    Si la fonctionnalité est critique pour l'expérience utilisateur ou l'accessibilité sur des environnements anciens, ajoutez un écouteur d'événements JavaScript (comme change ou input) qui ajoute une classe CSS .is-checked sur le parent pour émuler le comportement : 
    if (!CSS.supports('selector(:has(*))')) {
  // Ajout d'une classe de repli JS
  document.querySelectorAll('.product-card input').forEach(input => {
    input.addEventListener('change', () => {
      input.closest('.product-card').classList.toggle('is-selected', input.checked);
    });
  });
}
