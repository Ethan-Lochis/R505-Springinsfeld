@starting-style

Animez en toute fluidité l'entrée et la sortie d'éléments passant de display: none à visible, ainsi que les dialogues modaux et popovers natifs, sans timer JavaScript.

📖 1. Explication

Depuis la création des transitions CSS, un obstacle fondamental frustrait tous les développeurs : un élément qui passe de display: none à display: block (ou flex, grid) ne pouvait pas être animé à l'apparition. Dès que la propriété display changeait, le moteur de rendu appliquait instantanément l'état final, sans transition d'opacité ou de transformation.

Pour contourner ce problème, il fallait jongler avec des astuces JavaScript complexes : modifier la classe, forcer un recalcul de style (reflow) ou attendre la frame suivante avec un setTimeout() ou un requestAnimationFrame().

La règle @starting-style change totalement la donne. Associée au mot-clé allow-discrete (qui permet d'inclure des propriétés discrètes comme display ou overlay dans les transitions), elle permet de déclarer l'état de départ au tout premier rendu. Les éléments apparaissent et disparaissent ainsi avec des animations douces et naturelles, directement en pur CSS.

💻 2. Syntaxe

Voici la déclaration typique pour un panneau, un toast ou une modale :

CSS starting-style-syntax.css 
/* 1. L'élément dans son état normal affiché */
.toast {
  display: flex;
  opacity: 1;
  transform: translateY(0) scale(1);

  /* Autoriser les transitions sur les propriétés discrètes (display) */
  transition: 
    opacity 0.4s ease,
    transform 0.4s cubic-bezier(0.16, 1, 0.3, 1),
    display 0.4s allow-discrete;
}

/* 2. État initial lors de l'arrivée dans le DOM ou sortie de display:none */
@starting-style {
  .toast {
    opacity: 0;
    transform: translateY(20px) scale(0.95);
  }
}

/* 3. État masqué (pour la transition de sortie) */
.toast.is-hidden {
  display: none;
  opacity: 0;
  transform: translateY(20px) scale(0.95);
}

🛡️ 5. Note sur le Fallback & Stratégies de Repli

Comment utiliser @starting-style en toute sécurité dans vos projets web actuels ?

  • 1. Dégradation gracieuse native (Zéro risque de régression) :
    La beauté de @starting-style réside dans le fait qu'elle constitue une amélioration progressive naturelle. Un navigateur plus ancien qui ne comprend pas la règle ignore simplement le bloc @starting-style et la transition discrète : l'élément continuera de s'afficher ou de se masquer instantanément avec display: none / display: block, exactement comme il le faisait auparavant sans casser l'accessibilité.
  • 2. Conditionnement via la règle @supports :
    Si vous souhaitez appliquer une logique d'animation alternative sur les versions antérieures : 
    @supports (@starting-style {}) {
  .toast {
    transition: opacity 0.4s, transform 0.4s, display 0.4s allow-discrete;
  }
  
  @starting-style {
    .toast {
      opacity: 0;
      transform: translateY(10px);
    }
  }
}
  • 3. Respect impératif de prefers-reduced-motion :
    Pour respecter le confort des personnes sensibles au mal des transports ou troubles vestibulaires, désactivez les transitions de déplacement lorsque la préférence utilisateur est active : 
    @media (prefers-reduced-motion: reduce) {
  .toast, .dialog {
    transition: none !important;
  }
}
